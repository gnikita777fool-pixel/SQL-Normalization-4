### ЭТАП 1: Подготовка окружения (VS Code + Git-Bash + Docker)

1. Откройте **VS Code** и создайте новую папку для проекта (например, `Lab4_Normalization`).
2. Откройте встроенный терминал VS Code (`Ctrl + ~` или `Terminal -> New Terminal`). Убедитесь, что у вас используется **Git-Bash** (в правом верхнем углу терминала должно быть написано `bash` или `git-bash`).
3. Инициализируйте Git-репозиторий (так как требуется Git-Bash):
   ```bash
   git init
   ```
4. Убедитесь, что **Docker** запущен на вашем компьютере.

### ЭТАП 2: Теоретическая нормализация (до 3НФ)

Прежде чем писать SQL, нужно спроектировать структуру.
**Исходная таблица:** `Код заказа, Дата, Код клиента, Код товара, Название товара, Цена, Код представителя, Имя представителя, Количество`.

**Условие-ловушка:** *"один код заказа должен соответствовать только одному представителю"*. Это значит, что `Код заказа -> Код представителя`.

#### 1. Первая нормальная форма (1НФ)
*Правило:* Атомарность значений, отсутствие повторяющихся групп.
Таблица уже в 1НФ.
**Первичный ключ (ПК):** Составной — `(Код заказа, Код товара)`, так как в одном заказе может быть несколько товаров, а один товар может быть в разных заказах.

#### 2. Вторая нормальная форма (2НФ)
*Правило:* 1НФ + все неключевые атрибуты должны полностью зависеть от **всего** первичного ключа (устранение частичной зависимости).
*   `Дата`, `Код клиента`, `Код представителя`, `Имя представителя` зависят только от `Код заказа` (часть ключа).
*   `Название товара`, `Цена` зависят только от `Код товара` (часть ключа).
*   `Количество` зависит от обоих (от всего ключа).

**Разбиваем на таблицы:**
1.  **Заказы (Orders):** `Код заказа` (ПК), `Дата`, `Код клиента`, `Код представителя`, `Имя представителя`
2.  **Позиции заказа (Order_Items):** `Код заказа` (ЧК), `Код товара` (ЧК), `Количество`
3.  **Товары (Products):** `Код товара` (ПК), `Название товара`, `Цена`

#### 3. Третья нормальная форма (3НФ)
*Правило:* 2НФ + устранение транзитивных зависимостей (неключевой атрибут не должен зависеть от другого неключевого атрибута).
Смотрим на таблицу **Заказы**: `Имя представителя` зависит от `Код представителя`, который не является ключом. Это транзитивная зависимость.

**Итоговая структура (3НФ):**
1.  **Представители (Representatives):** `Код представителя` (ПК), `Имя представителя`
2.  **Товары (Products):** `Код товара` (ПК), `Название товара`, `Цена`
3.  **Заказы (Orders):** `Код заказа` (ПК), `Дата`, `Код клиента`, `Код представителя` (Внешний ключ)
4.  **Позиции заказа (Order_Items):** `Код заказа` (ЧК, Внешний ключ), `Код товара` (ЧК, Внешний ключ), `Количество`

*(Примечание: условие "один код заказа = один представитель" здесь соблюдено, так как в таблице Orders `Код заказа` является первичным ключом и определяет только одного представителя).*

### ЭТАП 3: Практическая реализация в Docker

1. **Запустите контейнер с базой данных** (например, PostgreSQL) через Docker CLI в терминале Git-Bash:
   ```bash
   docker run --name lab4_db -e POSTGRES_PASSWORD=mysecretpassword -d -p 5432:5432 postgres:latest
   ```
2. **Создайте SQL-файл** в VS Code. Назовите его `schema.sql`. Напишите в нем создание таблиц с учетом 3НФ и внешних ключей:
   ```sql
   CREATE TABLE Representatives (
       rep_id INT PRIMARY KEY,
       rep_name VARCHAR(100) NOT NULL
   );

   CREATE TABLE Products (
       prod_id INT PRIMARY KEY,
       prod_name VARCHAR(100) NOT NULL,
       price DECIMAL(10, 2) NOT NULL
   );

   CREATE TABLE Orders (
       order_id INT PRIMARY KEY,
       order_date DATE NOT NULL,
       client_id INT NOT NULL,
       rep_id INT NOT NULL,
       FOREIGN KEY (rep_id) REFERENCES Representatives(rep_id)
   );

   CREATE TABLE Order_Items (
       order_id INT,
       prod_id INT,
       quantity INT NOT NULL,
       PRIMARY KEY (order_id, prod_id),
       FOREIGN KEY (order_id) REFERENCES Orders(order_id),
       FOREIGN KEY (prod_id) REFERENCES Products(prod_id)
   );
   ```
   <img width="991" height="577" alt="image" src="https://github.com/user-attachments/assets/37c35059-4c95-4524-83b1-3a6fc1802a96" />

3. **Выполните SQL-скрипт** в базе данных:
   ```bash
   docker exec -i lab4_db psql -U postgres -c "\i /dev/stdin" < schema.sql
   ```
   *(Альтернативный вариант: зайти в консоль psql через `docker exec -it lab4_db psql -U postgres` и выполнить команды вручную).*

4. **Добавьте тестовые данные** (создайте файл `data.sql` и выполните его, чтобы база не была пустой).

### ЭТАП 4: Фиксация действий (Лог и Скриншоты)

<img width="349" height="145" alt="image" src="https://github.com/user-attachments/assets/db4bc86d-4da5-4f0f-aec5-9ce880df5ca0" />


1. **Создание лога:**
   В Git-Bash вы можете использовать команду `script`, которая записывает всё, что вы вводите в терминал, в файл.
   ```bash
   script actions.log
   ```
   *Теперь всё, что вы будете печатать в терминале (команды docker, psql и т.д.), будет сохраняться.*
   Выполните ваши команды (подключение к БД, вставка данных, проверка `SELECT * FROM ...`).
   Чтобы остановить запись, введите:
   ```bash
   exit
   ```
   *(Файл `actions.log` готов. Он содержит только ваши действия в консоли).*

2. **Скриншоты:**
   Сделайте скриншоты (можно вставить их прямо в README или положить в папку `screenshots/`):
   * Скриншот открытого VS Code с деревом файлов.
   * Скриншот терминала Git-Bash с запущенным Docker-контейнером.
   * Скриншот результата выполнения SQL-запросов (например, вывод `\dt` в psql, показывающий созданные таблицы).

### ЭТАП 5: Создание дампа базы данных

Сделайте дамп (резервную копию) вашей базы данных в формате SQL:
```bash
docker exec -t lab4_db pg_dump -U postgres > database_dump.sql
```
Теперь в вашей папке есть файл `database_dump.sql`.
